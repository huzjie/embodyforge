# 设计笔记

## 为什么 ZMP 是人形平衡的「单一真值」

人形机器人不会摔倒的充要条件是零力矩点（ZMP）落在双脚围成的支撑多边形内。
本项目的 balance 控制器就是一个 ZMP 预览控制器：用 LIPM 前推 CoM 轨迹、把指令
ZMP 夹回支撑多边形、再用「到多边形边界的距离」作为稳定裕度。所有跌倒检测、稳定
性基准都围绕这一个物理量展开，而不是另起一套经验规则。

## 为什么多机协同是一个「分布式系统」问题而非「控制」问题

110 台机器人同时跳舞，难点不在单机走得稳，而在「相位对齐」。单机各有晶振漂移，
要把它们锁到同一个节拍，用的就是 Kuramoto 弱耦合振子模型 + 逻辑时钟同步（NTP 式
均值），这是把分布式共识的成熟工具搬到机器人上的典型案例。

## 为什么训练信号要单调趋 1

`skill += lr(1-skill)` 是几何爬升、恒正。若用「对 +1 错 -1」，低起点 skill 的期望
漂移为负，会被压到 0——这是本系列项目反复踩过的坑。所有 mock 信号都遵循
`boost=(skill-0.5)*2`，skill=0.5 时 boost=0（随机基线）、1.0 时 boost=1（恒正确）。

## 为什么「声明规模与实例化解耦」

纯 Python 实例化 110 台 40 自由度的真实人形机器人会卡死。config 里分两层：
`declared`（110 台 / 40 DoF / A3 形态）只做口径表达，实际实例化 tiny 结构。
